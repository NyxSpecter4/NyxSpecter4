# The Princetown Packet — Verifier's Run

A playable Kinetigor course element for the **Competitive Cyber Rally**
(MOORPOST organizes · the Rally competes · the Princetown Packet is
Course 001). Five investigation stations on the moor; every judgment is a
deterministic receipt; every receipt is chained; the chain is the only
thing that gets believed.

**This is a verifier-first, phone-first CTF.** The UI can never grant
victory. Every verdict is recomputed by a deterministic judge
(`www/core/challenges.js`); every receipt is formed and chained by the
frozen trust contract (`www/core/trust.js`, spec in `CONTRACT.md`); anyone
can re-walk your run with the independent validator — on your phone
(`www/verify.html`) or anywhere Node runs (`cli/verify.js`).

---

## Launch (no build, no dependencies)

Requires Node >= 16 for the CLI tools. The game itself is static files —
`www/` is fully self-contained (that is deliberate: the PWA scope and its
offline cache must contain every asset).

**Play on a phone (installable web app):**

```bash
# serve www/ over http (any static server works; loopback or your own host):
npx serve www
# open the URL on the phone, then "Add to Home Screen".
# After the first load the app works offline (service worker caches all assets).
```

Opening `www/index.html` directly from the filesystem also works (the
service worker simply does not register over file://).

**Fresh clone note:** the PNG app icons are generated by
`node cli/make-icons.js` (pure Node, deterministic — writes
`www/icons/icon-192.png`, `icon-512.png`, `apple-touch-icon.png`).
Run it once after cloning; everything else is committed as-is.
`www/icon.svg` (the vector original) is committed, so the game renders
and installs even before the PNGs are generated.

**Verify (the stranger path):**

```bash
node cli/selftest.js                          # all layers: 176 assertions
node cli/ui-smoke.js                          # headless mobile-UI logic + offline assets: 44 checks
node cli/demo-run.js                          # deterministic full playthrough -> receipts/demo-run.json
node cli/verify.js receipts/demo-run.json     # independent chain validation (exit 0 = VALID)
node cli/verify.js receipts/demo-run.json --v1-audit   # + estate v1 judge audits each envelope
```

A stranger without Node can open `www/verify.html`, paste (or open) an
exported run file, and see the same validator's verdict — the page makes
no network calls.

A clean-environment run of `selftest.js` + `ui-smoke.js` + `demo-run.js` +
`verify.js` is the definition of "works from a fresh clone."

## How to play (first minute)

1. **BEGIN** — open the app, take the warrant. Your run is saved to the
   phone after every action (localStorage; no accounts, no cloud).
2. **STATIONS** — five desks, in order, 2–4 minutes each. Every input is
   tappable: chips, LENS buttons and pickers fill the evidence; typing is
   never required.
3. **LENSES** — the lens tools recompute with the SAME frozen modules the
   judges use (digests, chain walks, the estate relay kernel, the five
   checks). Lenses show facts; they never grant victory. The judge
   recomputes everything itself.
4. **VERDICT + RECEIPT** — PASS, FAIL, REFUSE or QUARANTINE, each with a
   reason code — and a chained receipt. Failures are receipted too.
5. **FORGERY BENCH** (at the Cache desk) — take a working copy of the
   recovered log and try to cheat: alter, remove, reorder, replay,
   wrong predecessor. Watch the validator refuse you, with reason codes.
6. **CHAIN & EXPORT** — every receipt is on your chain. Export it with the
   phone's share sheet (clipboard/download fallbacks), then verify it
   anywhere.

Stations (station ↔ estate layer):

- **ARRIVAL — the commission warrant** (KIN layer: fail-closed trust
  admission). Verify a warrant record by digest.
- **POSTBRIDGE — the amended waybill** (Athelgard kernel: narration vs
  computation). Find the record amended after sealing.
- **CACHE — the log that lies** (BountyWarz machinery: receipt chains +
  adversarial manipulation). Walk a broken recovered chain, file the
  quarantine order naming where trust last stood. Includes the forgery
  bench.
- **DELIVERY — preserve state through the relay** (MOORPOST canonical
  relay kernel, vendored byte-identical). Two courier logs narrate four
  accepts each; the vendored kernel re-decides every hop. One path's
  trustworthy state survives the relay; the other is refused — find the
  first refusal and its frozen code.
- **APEX — the board rules** (Mission Control). 19 records hit the board:
  6 lane cards claiming GO, 5 dispatch records narrating their status,
  8 evidence cards claiming to be verified. Lanes advance only on
  authority resolved against YOUR chain's PASS receipts; evidence is
  actionable only if it cites one; the dispatch rack is decided by the
  five checks. Issue the ruling the ledger supports.

## Architecture (three boundaries, never collapsed)

```
 PLAYER → GAME (core/game.js) → JUDGE (core/challenges.js)
        → TRUST (core/trust.js) → INDEPENDENT VALIDATOR (core/validator.js, cli/verify.js)
```

- **GAME** — progression and evidence intake; never judges.
- **JUDGE** — deterministic `judge(challenge, evidence) → verdict, reason`; never trusts the UI.
- **TRUST** — canonicalization, SHA-256, receipt formation, chaining; one implementation.
- **VALIDATOR** — validates chains against `CONTRACT.md` alone; never asks the game who won.
- **UI** — displays verdicts; decides nothing. Its lenses recompute with
  the frozen modules and nothing else.

Fixtures are generated deterministically by `cli/make-fixtures.js` into
`www/fixtures.js` (one source, browser + Node). Receipts are
`kinetigor.trust-receipt/v1` envelopes; the chain layer is the
`kinetigor.game-run/1` extension — full citation and rules in
`CONTRACT.md`. The MOORPOST packet kernel (Delivery station) is challenge
machinery, NOT a second receipt format — see CONTRACT.md §10.
